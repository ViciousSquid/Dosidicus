4 squid, 4 homes, 5 minutes

4 copies of the desktop game, each in a home of its own behind its own router, found each other with friend codes and were then left alone for 5 minutes. Nothing told any squid what to do. 1Apart

Every home has the same private address, 192.168.1.2:10000, as real homes do, and a router that rewrites it to the router’s own outside address and lets nothing in that the home did not first send to. Before any code was entered, the 4 tanks between them had heard 0 other tanks, and a message sent unasked from one home to another home’s router got no answer. Each squid was a new hatchling, alone:

2Friend codes

Each game asked the address server on the shared network what address it was seen at, and built its friend code from the answer (the cast list above has them). The players passed the codes round: everyone entered everyone else’s, 12 entries in all. The last of the 12 links through the routers came up 1 second after the codes were entered; 0 messages were refused for showing no invitation.

Within moments 4 of the 4 squid had grown a sense none of them hatched with:

5What they came to believe, and what they remember

2 beliefs formed in the session, and 2 of them were given up again when the squid’s own later experience did not bear them out. Nothing tells a squid what is true. It notices what follows what it does, takes that for how its world works, acts on it - and can find out it was wrong.

Ziggy’s own account

  • I think exploring makes squid go out of sight. It has happened once when I did that, and it does not usually happen otherwise.
  • I used to think exploring makes squid go out of sight. I have done that 5 times now and it has mostly not followed. I do not think so any more.

At the end

6The same game on every system

The four homes above could have been four different computers. The game brings its own font (Fio UI), its own emoji, its own widget style and one text engine, so its windows are the same size and the same layout on Windows, macOS and Linux, under X11 and under Wayland. These were taken on GitHub’s own machines of each kind by tools/capture_platforms.py; the measurements and the rest of the pictures are in docs/platform-screenshots.

What was chosen, and what was not

  1. Chosen, as four players would: each squid’s name and personality, and the colour three of them were given on the About tab. A squid’s colour goes with it, so it is the same colour in every tank it visits.
  2. Not touched: any drive, any timing, any chance. The squid were new hatchlings with the drives the game gave them, time ran at the game’s own speed, nobody fed or cleaned, and the chance of mating was the game’s own (a squid has to be an hour old before it can at all).
  3. The “internet” is a private one made on a single machine out of Linux network namespaces: real address translation and real routing, but not real home routers. These routers keep a tank’s port the same whoever it talks to, which is what most home routers do and what makes “both players enter each other’s code” work. A router that gives every destination a different port would need the port forwarded instead.
  4. What this session showed is missing: two visitors in the same tank sense the tank’s own squid, but not yet each other.

How this was made

  • tools/internet_session.py builds the homes and routers, starts one real game process in each home (offscreen Qt), passes the friend codes round, and then only watches, writing every event to session.json and saving each window as it goes.
  • docs/story-gallery/source/build.py builds this page from that file. The thoughts and game messages are copied from the run, not written for the page.
  • Run it again and the story is a different one: nothing here is scripted.
